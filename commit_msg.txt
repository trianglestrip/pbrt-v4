Overlap OptiX init with texture creation (CreateOptiXBundle on background thread)

Extract OptiX initialization into a static OptiXInitBundle / CreateOptiXBundle
(optixInit, device context, module compile, 16 program groups, pipeline) that
has no dependency on textures/materials, so it runs on the same background
thread as the PLY preload, concurrently with wpi-CreateTextures. The aggregate
ctor consumes the bundle (or initializes internally when none is passed).

SBT raygen/miss records are intentionally still allocated in the ctor on the
aggregate's memoryResource: they must outlive the aggregate, so they cannot
live in the throwaway allocator of the background-thread factory (that was a
use-after-free that crashed at first launch). The OptiXInitBundle carries only
OptiX handles.

bistro_cafe_quick: optix-init ~1.6 s -> ~0.01 s (overlapped); 3/3 exit 0;
output pixel-identical (imgtool diff MAE == 0). Documented in benchmark.md.
